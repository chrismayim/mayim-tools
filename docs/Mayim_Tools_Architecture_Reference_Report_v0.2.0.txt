1. EXECUTIVE SUMMARY
────────────────────────────────────────────────────────────────────────────────

Mayim Tools is a publicly redistributable QGIS 4+ plugin that delivers a
modular suite of engineering and geospatial processing tools organised into
clearly defined functional categories.

The plugin architecture follows a seven-tier layered design with a shared
Core Tools layer that provides reusable utilities accessible to all tool
categories. All tools are exposed through the QGIS Processing Framework,
ensuring compatibility with the QGIS Toolbox, Graphical Modeler, and Python
scripting console.

The plugin name "Mayim" is derived from the Hebrew word for water (מַיִם),
reflecting its initial focus on hydrological and water-related engineering
tools.

2. ARCHITECTURAL OVERVIEW
────────────────────────────────────────────────────────────────────────────────

The Mayim Tools plugin is structured as a seven-tier layered architecture.
All seven tiers have been implemented and validated in QGIS 4.0.3.

  TIER 1 │ QGIS 4+ HOST ENVIRONMENT
         │ PyQGIS API | Qt 6.11.1 / PyQt6 | Processing Framework
         │ Layer Registry | GDAL 3.13.0 | GEOS 3.14.1 | PROJ 9.8.1
         ▼
  TIER 2 │ PLUGIN ENTRY POINT
         │ metadata.txt | __init__.py | MayimToolsPlugin (main class)
         ▼
  TIER 3 │ CORE FRAMEWORK LAYER
         │ PluginManager | SettingsManager | Logger | EventBus | I18n
         ▼
  TIER 4 │ SHARED CORE TOOLS LAYER
         │ LayerUtils | GeomUtils | CRSManager | FileIO | ValidationUtils
         ▼
  TIER 5 │ CATEGORY REGISTRY LAYER
         │ Hydrology Tools | Geometry Tools | [Future categories]
         ▼
  TIER 6 │ UI / UX LAYER
         │ Toolbar | Dock Panel | Processing GUI | About Dialog
         ▼
  TIER 7 │ OUTPUT AND INTEGRATION LAYER
         │ QGIS Canvas | Processing Results | File Export | Provenance

ARCHITECTURAL PRINCIPLES

  Separation of Concerns:
    Each tier has a single, well-defined responsibility.

  Modularity:
    Tool categories are self-contained and independently deployable.

  Extensibility:
    New categories and tools are added via the registry pattern without
    modifying core code.

  Reusability:
    Core shared tools are stateless utilities consumed across all categories.

  Testability:
    All processing logic is decoupled from the UI, enabling headless unit
    testing.

  QGIS Compliance:
    Full adherence to QGIS plugin architecture standards and the QGIS
    Processing Framework API.

  Provenance-aware:
    Every tool produces a structured JSON provenance record and a human-
    readable text report alongside its raster outputs.

  Resolution-adaptive:
    Tool parameters scale with DEM resolution and vertical accuracy rather
    than using fixed, source-specific values.

5. CORE FRAMEWORK COMPONENTS
────────────────────────────────────────────────────────────────────────────────

5.1 Plugin Entry Point (mayim_tools_plugin.py)

The main plugin class implements the standard QGIS plugin lifecycle:

  __init__()   Initialises instance variables and logs startup.
  initGui()    Calls _cleanup() first to prevent duplicate entries, then
               registers the Processing Provider, sets up the toolbar,
               and sets up the dock widget.
  _cleanup()   Removes all GUI elements and deregisters the provider.
               Called by both initGui() and unload() to prevent
               duplicate toolbar/menu entries on plugin reload.
  unload()     Calls _cleanup() and logs unload.

NOTE: The main plugin menu has been removed. Tool access is provided via:
  - Processing Toolbox (primary access)
  - Dock panel tree (secondary access)
  - Toolbar category buttons (tertiary access)

5.2 Core Shared Utilities

All core modules are stateless utility classes or functions. They are
imported directly where needed, avoiding circular dependencies.

  Module               Responsibility
  ───────────────────────────────────────────────────────────────────────
  logger.py            Wraps QgsMessageLog with Info/Warning/Critical
  settings_manager.py  Reads/writes plugin settings via QSettings
  layer_utils.py       Layer listing, field access, type checking
  geometry_utils.py    Geometry validation, transformation, simplification
  crs_manager.py       CRS detection, EPSG lookup, reprojection
  file_io.py           GeoJSON, CSV, shapefile, GeoPackage read/write
  validation_utils.py  Null checks, type validation, range enforcement
  event_bus.py         Signal/slot-based pub/sub for inter-module messaging
  i18n_manager.py      Translation loading and locale detection

5.3 Category Registry

The CategoryRegistry allows each tool category to self-register at import
time. This eliminates the need for a hard-coded list of categories.

The categories/__init__.py file:
  - Calls CategoryRegistry.clear() to prevent duplicate registrations
    on plugin reload.
  - Imports each category module to trigger self-registration.
  - New categories are added by adding a single import line here.

5.4 Processing Provider

MayimToolsProvider registers all Mayim Tools algorithms with the QGIS
Processing Framework. This makes every tool available in:

  - The Processing Toolbox (GUI)
  - The Graphical Modeler (drag-and-drop workflows)
  - PyQGIS scripting: processing.run("mayimtools:toolname", {...})
  - QGIS processing history

5.5 Base Algorithm

All processing tools inherit from MayimBaseAlgorithm, which extends
QgsProcessingAlgorithm and enforces a consistent interface across all
tools. The base class provides:

  Abstract methods (must be implemented by every tool):
    name()              Unique algorithm identifier (lowercase, no spaces)
    displayName()       Human-readable name shown in the Toolbox
    group()             Category group name shown in the Toolbox
    groupId()           Unique category group identifier
    initAlgorithm()     Parameter definition
    processAlgorithm()  Core processing logic
    createInstance()    Required factory method

  Optional methods (override as needed):
    shortHelpString()   Help text shown in the Processing dialog
    helpUrl()           URL to full documentation
    tags()              Searchable tags for the Toolbox

  Shared helper methods (available to all tools):
    log()               Logs to QgsMessageLog and Processing feedback
    log_warning()       Logs a warning to both destinations
    is_cancelled()      Checks for user cancellation during processing
    set_progress()      Updates the Processing dialog progress bar

NOTE ON CAMELCASE METHOD NAMES:
  QGIS requires that override methods use camelCase naming, which
  conflicts with standard Python naming conventions (PEP 8). All
  camelCase override methods are annotated with # noqa: N802 to
  suppress the Ruff linter warning. Do NOT rename these methods to
  lowercase.

6.1 DEM Hydrological Screening

  File:         categories/hydrology/tools/dem_hydrological_screening.py
  Class:        DEMHydrologicalScreening
  Algorithm ID: mayimtools:demhydrologicalscreening
  Pipeline:     Stage 0 (Ingestion and QA) + Stage 1 (Artifact Screening)
  Status:       Implemented and deployed (plugin version 0.1.0)
  Dependencies: rasterio 1.5.1 | scipy 1.17.1 | numpy 2.4.6

  PURPOSE
  ───────
  Provides the first two stages of the Mayim Tools DEM hydrological
  conditioning pipeline. The tool must be run before any depression
  processing, smoothing, flow-direction, or flow-accumulation analysis.

  STAGE 0 — INGESTION AND QA
  ───────────────────────────
  Reads and validates the DEM and its metadata. Specifically:
    - Reads CRS, native resolution, extent, NoData value, data type,
      band count, and bounds.
    - Checks whether the CRS is projected or geographic and warns if
      geographic (degrees) when metric calculations may be required.
    - Assigns vertical accuracy (RMSE/LE90) from:
        (a) A user-supplied value, OR
        (b) A conservative default keyed to the declared source type.
    - Detects NoData (void) cells.
    - Labels connected void regions using scipy.ndimage.label().
    - Classifies voids by size:
        Small (<=10 cells, user-adjustable): interpolated using mean
          neighbourhood values.
        Medium (11-99 cells, user-adjustable): flagged in the void
          mask but not filled.
        Large (>=100 cells, user-adjustable): reported to the analyst
          as a data gap. Not filled. Analyst action required.
    - Writes the void classification mask (values 0-3).
    - Writes the screened DEM (small voids interpolated).

  STAGE 1 — ARTIFACT SCREENING
  ─────────────────────────────
  Classifies the DEM source type and screens for statistical outliers:
    - Classifies the DEM source from the user-selected option:
        Auto-detect | LiDAR DTM | LiDAR DSM | SRTM |
        Copernicus GLO-30 | FABDEM/FathomDEM | Aerial | Unknown
    - Applies a Median Absolute Deviation (MAD) local outlier filter
      using a sliding window (default 3x3, user-adjustable):
        For each valid cell, computes local median and MAD.
        Cells where |cell - median| / MAD > threshold are flagged.
        The filter detects speckle, striping, and scan-line noise.
        It does NOT modify elevations. It produces a binary mask only.
    - Writes the artifact mask (0 = clean, 1 = suspected artifact).

  CURRENTLY NOT IMPLEMENTED IN THIS TOOL:
    - LiDAR ground filtering (SMRF / Progressive TIN Densification).
    - Machine-learning or gradient-boosted bias correction.
    - Bare-earth product substitution (FABDEM, FathomDEM, GEDTM30).
    - Co-registered land-cover correction.
    These are flagged to the user with a clear advisory message.

  INPUTS
  ──────
  Parameter                     Type        Default  Notes
  ─────────────────────────────────────────────────────────────────────
  Input DEM                     Raster      Required
  DEM Source Type               Enum        0        Auto-detect
  Known vertical accuracy RMSE  Double      -1.0     -1 = use default
  Small void threshold          Integer     10       cells
  Large void threshold          Integer     100      cells
  Artifact filter window size   Integer     3        must be odd
  Artifact detection threshold  Double      3.0      sigma
  Output folder                 Folder      Required
  Load screened DEM             Boolean     True
  Load void mask                Boolean     True
  Load artifact mask            Boolean     True

  VERTICAL ACCURACY DEFAULTS BY SOURCE TYPE
  ──────────────────────────────────────────
  Source Type                   Default RMSE
  ─────────────────────────────────────────────
  LiDAR bare-earth (DTM)        0.15 m
  LiDAR surface model (DSM)     0.40 m
  SRTM (30m / 90m)              4.00 m
  Copernicus GLO-30             4.00 m
  FABDEM / FathomDEM / GEDTM30  1.50 m
  Aerial photogrammetry         0.75 m
  Unknown / Other               5.00 m (conservative)

  OUTPUTS
  ───────
  File                              Description
  ─────────────────────────────────────────────────────────────────────
  <dem>_screened.tif                DEM with small voids interpolated
  <dem>_void_mask.tif               Void classification raster (0-3)
  <dem>_artifact_mask.tif           MAD outlier mask (0=clean, 1=artifact)
  <dem>_screening_report.txt        Human-readable QA report
  <dem>_provenance.json             Machine-readable provenance record

  VOID MASK VALUES
  ────────────────
  Value  Meaning
  ─────────────────────────────────────────────────────────────────────
  0      Valid data cell
  1      Small void — interpolated by this tool
  2      Medium void — flagged, not filled
  3      Large void — reported to analyst, not filled
  255    NoData (outside valid area)

  ARTIFACT MASK VALUES
  ────────────────────
  Value  Meaning
  ─────────────────────────────────────────────────────────────────────
  0      Clean cell
  1      Suspected artifact (MAD outlier)
  255    NoData (outside valid area)

  KNOWN LIMITATIONS
  ─────────────────
  - MAD filter is a statistical screening tool only. It does not
    distinguish artifact noise from genuine sharp terrain breaks.
    Review the artifact mask before any downstream modifications.
  - The tool does not automatically correct artifacts. It identifies
    and reports them.
  - Large void regions are not filled. They must be addressed by the
    analyst before proceeding.
  - The screened DEM retains all original elevation values except
    where small voids have been interpolated.


6.2 DEM Hydrological Smoothing

  File:         categories/hydrology/tools/dem_hydrological_smoothing.py
  Class:        DEMHydrologicalSmoothing
  Algorithm ID: mayimtools:demhydrologicalsmoothing
  Pipeline:     Stage 2 (Controlled Smoothing)
  Status:       Implemented and deployed (plugin version 0.1.0)
  Dependencies: rasterio 1.5.1 | numpy 2.4.6

  PURPOSE
  ───────
  Implements Stage 2 of the Mayim Tools DEM hydrological conditioning
  pipeline. Reduces residual high-frequency noise using an edge-
  preserving anisotropic diffusion filter. The input DEM is never
  overwritten.

  This tool should only be used after:
    (a) The Stage 0/1 screening report has been reviewed.
    (b) The artifact mask has been inspected.
    (c) Residual high-frequency noise has been confirmed.

  It should NOT be used as an automatic preprocessing step applied
  to every DEM regardless of noise characteristics.

  METHOD — PERONA-MALIK ANISOTROPIC DIFFUSION
  ────────────────────────────────────────────
  Reference: Perona, P. and Malik, J. (1990). Scale-space and edge
  detection using anisotropic diffusion. IEEE Transactions on Pattern
  Analysis and Machine Intelligence, 12(7), 629-639.

  The algorithm:
    1. Initialises the working array from the input DEM.
    2. Sets NoData and non-finite cells to NaN internally.
    3. For each iteration:
       a. Computes elevation gradients to four-connected neighbours
          (north, south, east, west).
       b. Applies a conductance function:
            conductance = exp(-(|gradient| / edge_threshold)^2)
          This reduces diffusion strength across larger gradients,
          preserving terrain edges.
       c. Updates each valid cell:
            new_value = current + strength * sum(conductance * gradient)
       d. Logs iteration progress.
    4. Restores original values in NoData cells.
    5. Computes difference and modification mask.
    6. Writes outputs.

  RESOLUTION SCALING
  ──────────────────
  When resolution scaling is enabled, the effective diffusion strength
  is scaled by:

    factor = clip(1.0 / mean_resolution, 0.1, 1.0)

  where mean_resolution is the mean cell size in map units.
  The reference resolution is 1 metre.

  Effect by resolution:
    1 m DEM   factor = 1.0   full diffusion strength applied
    5 m DEM   factor = 0.2   reduced diffusion strength
    30 m DEM  factor = 0.1   minimum diffusion strength (clipped)

  This prevents over-smoothing of coarse-resolution DEMs where each
  cell already represents a large ground area.

  INPUTS
  ──────
  Parameter                           Type      Default  Notes
  ─────────────────────────────────────────────────────────────────────
  Input DEM                           Raster    Required
  Diffusion iterations                Integer   5        range: 1-100
  Diffusion strength                  Double    0.20     range: 0.01-0.25
  Edge threshold in elevation units   Double    1.0      range: >0
  Scale diffusion by DEM resolution   Boolean   True
  Output folder                       Folder    Required
  Load smoothed DEM                   Boolean   True
  Load smoothing difference raster    Boolean   True
  Load smoothing mask                 Boolean   True

  RECOMMENDED STARTING VALUES BY DEM CONDITION
  ─────────────────────────────────────────────
  DEM condition               Iterations  Strength  Edge threshold
  ─────────────────────────────────────────────────────────────────
  Clean LiDAR DTM             1-3         0.10-0.15  ~1-2x RMSE
  Light residual noise        3-5         0.15-0.20  ~1x RMSE
  Moderate high-freq noise    5-10        0.20-0.25  ~1-2x RMSE
  Strong or systematic noise  Review Stage 1 and DEM source first

  EDGE THRESHOLD GUIDANCE
  ───────────────────────
  The edge threshold is expressed in the elevation units of the DEM.
  For a DEM in metres, it is in metres.

  Lower values:
    - Preserve terrain edges more strongly.
    - Reduce smoothing across elevation breaks.
    - Appropriate for clean or well-surveyed terrain.

  Higher values:
    - Allow more smoothing across larger gradients.
    - May reduce the distinction between noise and genuine terrain.
    - Use cautiously.

  Where a reliable RMSE is available, an initial sensitivity test
  around one to two times the RMSE may be useful as a starting
  heuristic. This is not an automatic accuracy correction.

  OUTPUTS
  ───────
  File                                  Description
  ─────────────────────────────────────────────────────────────────────
  <dem>_smoothed.tif                    Edge-preserving smoothed DEM
  <dem>_smoothing_difference.tif        smoothed - original (signed)
  <dem>_smoothing_mask.tif              Modification mask (0=unchanged,
                                        1=modified, 255=NoData)
  <dem>_smoothing_report.txt            Human-readable smoothing report
  <dem>_smoothing_provenance.json       Machine-readable provenance

  DIFFERENCE RASTER INTERPRETATION
  ─────────────────────────────────
  Value     Meaning
  ─────────────────────────────────────────────────────────────────────
  Negative  Smoothing lowered the cell elevation
  Positive  Smoothing raised the cell elevation
  Zero      No effective change

  SMOOTHING MASK VALUES
  ─────────────────────
  Value  Meaning
  ─────────────────────────────────────────────────────────────────────
  0      Unchanged or negligible change
  1      Cell modified by smoothing
  255    NoData (outside valid area)

  KNOWN LIMITATIONS
  ─────────────────
  - The current implementation applies diffusion to ALL valid cells,
    not only cells flagged by the Stage 1 artifact mask. A future
    version may add an optional artifact-mask input to restrict
    smoothing to flagged or buffered regions only.
  - The diffusion strength maximum of 0.25 is a numerical stability
    limit for the four-connected explicit scheme. It is not a
    physically meaningful limit.
  - Resolution scaling reduces diffusion strength but does not scale
    the number of iterations or the kernel neighbourhood.
  - This tool does not fill or breach depressions and does not
    calculate flow direction or accumulation.

KEY DESIGN PRINCIPLES FROM THE RESEARCH PAPER

  1. Classify before modifying.
     No cell elevation is changed until the depression it belongs to
     has been assessed. A depression that looks like an artifact may
     be a genuine hydrological feature. Automatic erasure without
     classification is not acceptable in a rigorous pipeline.

  2. Separate artifact correction from hydrological enforcement.
     Improving the DEM so that it better represents the underlying
     terrain (artifact correction) is a fundamentally different
     operation from modifying the terrain so that flow-routing
     algorithms can operate consistently (hydrological enforcement).
     These two operations must not be conflated.

  3. Prefer least-impact intervention.
     Constrained least-cost breaching is the preferred default for
     depression resolution. Filling is a fallback applied only where
     breaching cannot resolve the depression. Genuine closed basins
     are preserved, not erased.

  4. Preserve genuine closed basins.
     Real depressions such as potholes, dolines, playas, and
     endorheic basins are retained as first-class hydrological
     objects. They are not automatically filled.

  5. Every modification must be traceable.
     The pipeline emits a cell-level audit raster and a structured
     metadata log for every run. No cell elevation is changed
     without a corresponding provenance record.

  6. Resolution-adaptive behaviour.
     All thresholds and parameters scale with DEM resolution and
     vertical accuracy rather than using fixed values. The same
     configuration must behave sensibly on both 1 m and 30 m inputs.

  7. Large voids are reported, not silently filled.
     Large NoData regions typically indicate a genuine data-collection
     gap. No conditioning algorithm should paper over such gaps
     invisibly. They are reported to the analyst for explicit action.

8. CATEGORY DESIGN PATTERN
────────────────────────────────────────────────────────────────────────────────

8.1 Category Self-Registration Pattern

Each category registers itself automatically when imported:

  In categories/hydrology/__init__.py:
    from mayim_tools.categories.category_registry import CategoryRegistry
    from mayim_tools.categories.hydrology.category import HydrologyCategory
    CategoryRegistry.register(HydrologyCategory())

  In categories/__init__.py:
    CategoryRegistry.clear()                 prevents duplicates on reload
    import mayim_tools.categories.hydrology  triggers self-registration
    import mayim_tools.categories.geometry   triggers self-registration

8.2 Adding a New Category

To add a new tool category:
  1. Create folder: mayim_tools/categories/[category_name]/
  2. Create: __init__.py (self-registers on import)
  3. Create: category.py (inherits BaseCategory)
  4. Create: tools/__init__.py
  5. Add import to: mayim_tools/categories/__init__.py
  6. Add icon to: mayim_tools/icons/
  7. Add icon reference to: mayim_tools/resources.qrc

8.3 Adding a New Tool

To add a new tool to an existing category:
  1. Create: mayim_tools/categories/[category]/tools/[tool_name].py
  2. Inherit from MayimBaseAlgorithm
  3. Implement all required abstract methods
  4. Add # noqa: N802 to all camelCase QGIS override methods
  5. Register in: mayim_tools/categories/[category]/category.py
                  inside the get_algorithms() method
  6. Write a test in: tests/test_categories/
  7. Add a chapter to: docs/user_manual/Mayim_Tools_User_Manual.md
  8. Update CHANGELOG.md

8.4 Tool Output Pattern

Every tool should produce:
  - One or more raster outputs (GeoTIFF, LZW compressed)
  - A human-readable text report (.txt)
  - A machine-readable provenance record (.json)
  - Optionally load results directly into the QGIS project

Output naming convention:
  <input_dem_stem>_<descriptor>.tif
  <input_dem_stem>_<descriptor>_report.txt
  <input_dem_stem>_<descriptor>_provenance.json

8.5 Base Algorithm Pattern

All tools inherit from MayimBaseAlgorithm:

  from mayim_tools.processing.algorithms.base_algorithm import (
      MayimBaseAlgorithm,
  )

  class MyTool(MayimBaseAlgorithm):

      def name(self) -> str:              # noqa: N802 (QGIS override)
          return "mytoolname"

      def displayName(self) -> str:       # noqa: N802 (QGIS override)
          return "My Tool Name"

      def group(self) -> str:             # noqa: N802 (QGIS override)
          return "Hydrology Tools"

      def groupId(self) -> str:           # noqa: N802 (QGIS override)
          return "hydrology"

      def createInstance(self):           # noqa: N802 (QGIS override)
          return MyTool()

      def initAlgorithm(self, config=None) -> None:  # noqa: N802
          # Add input and output parameters here
          pass

      def processAlgorithm(              # noqa: N802 (QGIS override)
          self,
          parameters: dict,
          context: QgsProcessingContext,
          feedback: QgsProcessingFeedback,
      ) -> dict:
          # Tool logic here
          return {}

9.3 Known Environment Issues

  Issue 1: pre-commit disabled
    pre-commit hooks are disabled due to a conflict between the QGIS
    Python environment (bin\python.exe) and pre-commit's virtual
    environment creation. The PYTHONHOME environment variable is not
    correctly resolved when pre-commit attempts to create isolated
    virtual environments.
    Workaround: Run mayim-format and mayim-lint manually before each
    commit.

  Issue 2: QGIS profile folder is QGIS4 not QGIS3
    QGIS 4.0.3 uses the QGIS4 profile folder:
      C:\Users\caets\AppData\Roaming\QGIS\QGIS4\profiles\default\
    The deploy script is configured accordingly. Do not deploy to the
    QGIS3 folder.

  Issue 3: Use apps\Python312\python.exe not bin\python.exe
    The correct Python executable for development is:
      C:\Program Files\QGIS 4.0.3\apps\Python312\python.exe
    Using bin\python.exe causes a PYTHONHOME resolution error and
    prevents pip and module imports from working correctly.

  Issue 4: resources_rc.py is a development stub
    pyrcc6 is not available in the QGIS 4.0.3 installation. The
    resources_rc.py file is a manually created stub that provides a
    get_icon_path() helper function. Icons are loaded from file paths
    rather than from compiled Qt resources. Replace with a properly
    compiled resources_rc.py for any production release.

  Issue 5: Icons are placeholders
    The current icons are simple 32x32 coloured PNG files created
    programmatically. They should be replaced with professional
    SVG or PNG icons before any public release.

  Issue 6: Plugin restart required after deploy
    Due to Python module caching, a full QGIS restart is required
    after deploying code changes. Disabling and re-enabling the plugin
    via the Plugin Manager may not reliably reload all changed modules,
    particularly when algorithm definitions or parameter structures
    have changed.

  Issue 7: QGIS camelCase method naming
    QGIS requires that Processing algorithm override methods use
    camelCase naming (e.g. displayName, groupId, initAlgorithm).
    This conflicts with Python PEP 8 naming conventions and triggers
    Ruff rule N802. All affected methods are annotated with
    # noqa: N802. Do NOT rename these methods to lowercase.

  Issue 8: Duplicate layers on re-run
    When a tool is run more than once in the same QGIS session with
    load options enabled, duplicate layers may be added to the project.
    The user should remove previous output layers before re-running.

14. CODE CONVENTIONS
────────────────────────────────────────────────────────────────────────────────

14.1 General

  - All files use UTF-8 encoding.
  - The UTF-8 encoding declaration (# -*- coding: utf-8 -*-)
    is NOT required in Python 3 and should be omitted.
  - All classes and methods have docstrings.
  - Type hints are used throughout.
  - Line length: 88 characters (black default).
  - Indentation: 4 spaces. No tabs.

14.2 Naming Conventions

  Classes:        PascalCase          MayimLogger, HydrologyCategory
  Functions:      snake_case          get_algorithms, is_valid_layer
  Constants:      UPPER_SNAKE_CASE    PLUGIN_NAME, PROVIDER_ID
  Files:          snake_case          layer_utils.py, base_algorithm.py
  Category IDs:   snake_case string   "hydrology", "geometry"
  Algorithm IDs:  lowercase string    "demhydrologicalscreening"

14.3 QGIS Override Methods

  QGIS Processing algorithm override methods use camelCase as imposed
  by the QGIS API. These must NOT be renamed to snake_case. Each
  camelCase override method must be annotated with # noqa: N802.

  Required QGIS override methods:
    name()              # noqa: N802
    displayName()       # noqa: N802
    group()             # noqa: N802 (if overriding)
    groupId()           # noqa: N802
    createInstance()    # noqa: N802
    shortHelpString()   # noqa: N802 (if overriding)
    helpUrl()           # noqa: N802 (if overriding)
    initAlgorithm()     # noqa: N802
    processAlgorithm()  # noqa: N802

14.4 Import Order (Ruff enforced)

  1.  Standard library imports (json, pathlib, datetime, etc.)
  2.  Third-party imports (numpy, rasterio, scipy, etc.)
  3.  QGIS imports (qgis.core, qgis.PyQt, etc.)
  4.  Local mayim_tools imports

14.5 Logging Convention

  Use MayimLogger exclusively. Never use print() in production code.

    MayimLogger.info("message")      General information
    MayimLogger.warning("message")   Non-critical issues
    MayimLogger.critical("message")  Errors
    MayimLogger.success("message")   Successful operations

  Inside processAlgorithm(), also use the feedback object:
    self.log("message", feedback)          Info to Processing panel
    self.log_warning("message", feedback)  Warning to Processing panel

14.6 Error Handling Convention

  All processAlgorithm() implementations wrap the main processing
  block in try/except:

    try:
        with rasterio.open(path) as source:
            # processing logic

    except QgsProcessingException:
        raise                          Re-raise QGIS exceptions directly

    except Exception as error:
        MayimLogger.critical(f"Tool failed: {error}")
        raise QgsProcessingException(
            f"Tool failed: {error}"
        ) from error

14.7 Output File Naming Convention

  Pattern:
    <input_dem_stem>_<descriptor>.tif
    <input_dem_stem>_<descriptor>_report.txt
    <input_dem_stem>_<descriptor>_provenance.json

  Examples:
    watershed_dem_screened.tif

    watershed_dem_artifact_mask.tif
    watershed_dem_screening_report.txt

17. GLOSSARY
────────────────────────────────────────────────────────────────────────────────

  Algorithm ID
    The unique string identifier used to call a Processing algorithm
    from Python. Format: "providerid:algorithmname".
    Example: "mayimtools:demhydrologicalscreening".

  Anisotropic diffusion
    An edge-preserving image smoothing technique that reduces diffusion
    across strong gradients. Used in Stage 2 of the pipeline.

  Artifact
    An elevation value in a DEM that does not represent the true terrain
    surface. Sources include vegetation, buildings, radar noise,
    striping, and interpolation errors.

  Artifact correction
    The process of improving a DEM so that it better represents the
    underlying terrain. Distinct from hydrological enforcement.

  BaseCategory
    The abstract Python base class that all Mayim Tools category
    descriptors must inherit from.

  CategoryRegistry
    The central registry that tracks all registered Mayim Tools
    categories. Categories self-register on import.

  CRS
    Coordinate Reference System. Defines how coordinates relate to
    locations on the Earth's surface.

  DEM
    Digital Elevation Model. A raster representation of terrain
    elevation values.

  Depression
    A cell or group of cells in a DEM that is lower than all
    surrounding cells, preventing modelled water from draining.

  DSM
    Digital Surface Model. A DEM that includes above-ground features
    such as vegetation and buildings.
  
  DTM
    Digital Terrain Model. A DEM representing the bare-earth surface,
    with above-ground features such as vegetation and buildings removed.

  Edge threshold
    A parameter controlling the sensitivity of the anisotropic diffusion
    filter to elevation gradients. Expressed in the elevation units of
    the input DEM. Lower values preserve stronger terrain edges.

  Endorheic basin
    A closed drainage basin with no outflow to the ocean. Water
    accumulates internally. A genuine hydrological feature that should
    not be automatically filled.

  FABDEM
    Forest And Buildings removed Copernicus DEM. A corrected global
    DEM product with vegetation and building bias removed.
    Reference: Hawker et al. (2022).

  FathomDEM
    A corrected global DEM product. Similar in intent to FABDEM.

  GEDTM30
    Global Enhanced Digital Terrain Model at 30 m resolution.
    A corrected global bare-earth product.

  Geographic CRS
    A coordinate reference system using angular units (degrees of
    latitude and longitude). Not suitable for metric calculations
    such as area, distance, or resolution-based thresholds.

  GPL-2.0+
    GNU General Public License version 2 or later. The open-source
    licence under which Mayim Tools is distributed. Required for
    submission to the QGIS Plugin Repository.

  Hydrological conditioning
    The process of modifying a DEM so that flow-routing algorithms
    produce hydrologically consistent results. Includes depression
    filling, breaching, flat-area resolution, and related operations.

  Hydrological enforcement
    Modification of terrain elevations to ensure consistent modelled
    flow paths. Distinct from artifact correction.

  InSAR
    Interferometric Synthetic Aperture Radar. A radar-based remote
    sensing technique used to produce elevation models. InSAR DEMs
    are susceptible to noise, striping, and phase-unwrapping artifacts.

  LE90
    Linear Error at 90 percent confidence. A vertical accuracy metric
    indicating that 90 percent of measured elevations fall within the
    stated error bound of the true elevation.

  LiDAR
    Light Detection and Ranging. An active remote sensing technique
    using laser pulses to measure terrain elevation. Typically produces
    high-accuracy, high-resolution elevation data.

  MAD
    Median Absolute Deviation. A robust statistical measure of
    variability used in the Stage 1 artifact screening filter.
    MAD = median(|x - median(x)|).
    Reference: Leys et al. (2013).

  MayimBaseAlgorithm
    The abstract Python base class that all Mayim Tools Processing
    algorithms must inherit from.

  NoData
    A designated value in a raster dataset indicating that no valid
    measurement exists for that cell. Also referred to as a void.

  Perona-Malik diffusion
    An anisotropic diffusion method that applies a conductance function
    to reduce smoothing across strong elevation gradients.
    Reference: Perona and Malik (1990).

  Priority-Flood
    An optimal depression-filling and watershed-labelling algorithm
    for digital elevation models.
    Reference: Barnes et al. (2014).

  Processing Provider
    A QGIS Processing Framework component that groups related
    algorithms under a named provider. The Mayim Tools provider ID
    is "mayimtools".

  Projected CRS
    A coordinate reference system using linear units (metres or feet).
    Required for distance-dependent and area-dependent calculations.

  Provenance
    A structured record of the inputs, parameters, decisions, and
    outputs associated with a processing operation. Supports
    reproducibility, auditability, and peer review.

  RMSE
    Root Mean Square Error. A measure of vertical accuracy expressing
    the typical difference between measured and true elevations.

  SAR
    Synthetic Aperture Radar. A radar-based remote sensing technique.
    SAR-derived DEMs are susceptible to speckle, layover, shadow,
    and phase-unwrapping artifacts.

  Screened DEM
    The output DEM produced by the DEM Hydrological Screening tool.
    Small voids have been interpolated. Artifact cells have been
    identified but not modified.

  SemVer
    Semantic Versioning. A versioning scheme using the format
    MAJOR.MINOR.PATCH. See semver.org.

  SMRF
    Simple Morphological Filter. A ground-filtering algorithm for
    LiDAR point clouds used to classify ground and non-ground returns.
    Reference: Pingel et al. (2013).

  SRTM
    Shuttle Radar Topography Mission. A global DEM dataset produced
    from InSAR measurements at approximately 30 m resolution.

  Void
    A NoData cell in a raster dataset. May result from data collection
    gaps, cloud cover, radar shadow, or processing artifacts.

  Void mask
    A raster output classifying each cell as valid data, small void
    (interpolated), medium void (flagged), or large void (reported).

  XGBoost correction
    A machine-learning approach using gradient-boosted trees to
    correct vegetation and building bias in satellite-derived DEMs.
    Used in the FABDEM production pipeline.

18. APPENDIX A — PROCESSING PARAMETER CONVENTIONS
────────────────────────────────────────────────────────────────────────────────

A.1 Parameter Naming

  All parameter identifiers use UPPER_SNAKE_CASE:
    INPUT_DEM
    DEM_SOURCE_TYPE
    OUTPUT_FOLDER
    LOAD_SCREENED_DEM

  All output identifiers use UPPER_SNAKE_CASE with OUTPUT_ prefix:
    OUTPUT_DEM
    OUTPUT_VOID_MASK
    OUTPUT_REPORT
    OUTPUT_PROVENANCE

A.2 Optional Parameters

  Optional parameters use optional=True in the parameter constructor.
  Where a numeric parameter has a sentinel value indicating "not set",
  use -1.0 as the sentinel and document this in the parameter label.
  Example:
    Known vertical accuracy RMSE (m) — leave -1 to use default

A.3 Boolean Load Parameters

  Each tool that produces raster outputs should include one Boolean
  parameter per output raster, controlling whether that layer is
  automatically loaded into the QGIS project after processing.
  Default value: True.
  Parameter naming convention:
    LOAD_<OUTPUT_DESCRIPTOR>
  Examples:
    LOAD_SCREENED_DEM
    LOAD_VOID_MASK
    LOAD_ARTIFACT_MASK
    LOAD_SMOOTHED_DEM
    LOAD_DIFFERENCE
    LOAD_SMOOTHING_MASK

A.4 Output Type Declarations

  Raster outputs that are loaded manually via project.addMapLayer()
  should be declared as QgsProcessingOutputFile, not as
  QgsProcessingOutputRasterLayer. Using QgsProcessingOutputRasterLayer
  alongside manual loading may cause duplicate layers to appear.

  Use QgsProcessingOutputFile for all raster and file outputs where
  manual loading with checkboxes is implemented.

A.5 Temporary Output Handling

  When the user selects TEMPORARY_OUTPUT or leaves the output folder
  empty, the tool should create a temporary directory using:
    import tempfile
    output_folder = tempfile.mkdtemp(prefix="mayim_<toolname>_")

  Temporary outputs may be removed when the QGIS session ends.
  Users should be advised to write important outputs to a permanent
  project directory.

A.6 Recommended Parameter Value Documentation

  Each numeric parameter label should include:
    (recommended: X; valid range: Y-Z)
  Example:
    "Diffusion iterations (recommended: 5; valid range: 1-100)"

  This makes guidance visible directly in the Processing dialog
  without requiring the user to open the help panel.

  <dem>_smoothed.tif                Smoothed DEM

  <dem>_smoothing_mask.tif          Smoothing modification mask

  Elevation DEM  float32      Source nodata   Preserves source nodata
  Difference     float32      -9999.0         Signed elevation change
  Class mask     uint8        255             Integer class values
  Binary mask    uint8        255             0=unchanged, 1=modified
