SECTION 2 — WHAT MAYIM TOOLS IS
─────────────────────────────────────────────────────────────────────────────
Mayim Tools is a publicly redistributable QGIS 4+ plugin designed for
engineering and geospatial analysis. The name "Mayim" comes from the Hebrew
word for "water" (מַיִם), reflecting its initial focus on hydrological and
water-related engineering tools.

The plugin provides a categorised suite of processing tools accessible via:
  • The QGIS Processing Toolbox
  • The QGIS Graphical Modeler
  • The QGIS Python Console (processing.run())
  • A custom Dock Panel (category/tool browser)
  • A custom Plugin Menu (Plugins > Mayim Tools)
  • A custom Toolbar

Repository:   https://github.com/chrismayim/mayim-tools
License:      GNU General Public License v2.0 or later (GPL-2.0+)
Status:       Active development — architecture complete, tools in progress

SECTION 5 — ARCHITECTURE DESIGN PATTERNS
─────────────────────────────────────────────────────────────────────────────
5.1 CATEGORY SELF-REGISTRATION PATTERN
Each category registers itself automatically when imported:

    # In categories/hydrology/__init__.py:
    from mayim_tools.categories.category_registry import CategoryRegistry
    from mayim_tools.categories.hydrology.category import HydrologyCategory
    CategoryRegistry.register(HydrologyCategory())

    # In categories/__init__.py:
    CategoryRegistry.clear()                    # prevent duplicates on reload
    import mayim_tools.categories.hydrology     # triggers self-registration
    import mayim_tools.categories.geometry      # triggers self-registration

5.2 ADDING A NEW CATEGORY
To add a new tool category:
    1. Create folder: mayim_tools/categories/[category_name]/
    2. Create: __init__.py (self-registers)
    3. Create: category.py (inherits BaseCategory)
    4. Create: tools/ folder
    5. Add import to: mayim_tools/categories/__init__.py

5.3 ADDING A NEW TOOL
To add a new tool to an existing category:
    1. Create: mayim_tools/categories/[category]/tools/[tool_name].py
    2. Inherit from MayimBaseAlgorithm
    3. Implement: name(), displayName(), group(), groupId(),
                  initAlgorithm(), processAlgorithm(), createInstance()
    4. Register in: mayim_tools/categories/[category]/category.py
                    inside get_algorithms() method

5.4 BASE ALGORITHM PATTERN
All tools inherit from MayimBaseAlgorithm:

    from mayim_tools.processing.algorithms.base_algorithm import (
        MayimBaseAlgorithm
    )

    class MyTool(MayimBaseAlgorithm):
        def name(self):         return "mytool"
        def displayName(self):  return "My Tool"
        def group(self):        return "Hydrology Tools"
        def groupId(self):      return "hydrology"
        def createInstance(self): return MyTool()

        def initAlgorithm(self, config=None):
            # Add input/output parameters here
            pass

        def processAlgorithm(self, parameters, context, feedback):
            # Tool logic here
            return {}

5.5 CORE UTILITIES USAGE
All core utilities are static classes — import and use directly:

    from mayim_tools.core.logger import MayimLogger
    from mayim_tools.core.validation_utils import ValidationUtils
    from mayim_tools.core.layer_utils import LayerUtils
    from mayim_tools.core.crs_manager import CRSManager
    from mayim_tools.core.settings_manager import SettingsManager

    MayimLogger.info("message")
    MayimLogger.warning("message")
    MayimLogger.critical("message")

    ValidationUtils.is_valid_vector_layer(layer)
    ValidationUtils.is_positive_number(value)
    ValidationUtils.is_in_range(value, min, max)

    LayerUtils.get_vector_layers()
    LayerUtils.get_layer_by_name("name")

    CRSManager.from_epsg(32735)
    CRSManager.project_crs()

    SettingsManager.set("key", value)
    SettingsManager.get("key", default)

SECTION 12 — INSTRUCTIONS FOR AI ASSISTANT
─────────────────────────────────────────────────────────────────────────────
When assisting with Mayim Tools development, please:

1. ALWAYS follow the established architecture patterns described above.
   Do not suggest alternative structures — the architecture is fixed.

2. ALWAYS use MayimBaseAlgorithm as the base for new tools.
   Never create standalone QgsProcessingAlgorithm subclasses.

3. ALWAYS register new tools in the category's get_algorithms() method.
   Never hard-code tool lists anywhere else.

4. ALWAYS use the core utilities (MayimLogger, ValidationUtils, etc.)
   Never use print() or raw QgsMessageLog calls in tool code.

5. ALWAYS include complete docstrings on all classes and methods.
   Follow the existing docstring style in the codebase.

6. ALWAYS use type hints on all function signatures.

7. ALWAYS wrap processing logic in try/except with MayimLogger.critical().

8. WHEN adding a new category:
   - Create the folder structure
   - Inherit from BaseCategory
   - Add import to categories/__init__.py
   - Add icon to resources.qrc

9. WHEN adding a new tool:
   - Create in the correct category's tools/ folder
   - Inherit from MayimBaseAlgorithm
   - Register in category's get_algorithms()
   - Write a test in tests/test_categories/

10. CODE STYLE:
    - Line length: 88 characters
    - Formatter: black
    - Linter: ruff
    - Python: 3.12
