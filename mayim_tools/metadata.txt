about=Mayim Tools is a QGIS Processing plugin developed by Mayim Consulting, providing a suite of hydrology, rainfall and data processing tools. Rainfall Tools group: Design Rainfall Estimation (South Africa); point extraction of CHIRPS, IMERG, MERRA-2, CMORPH and PERSIANN CDR precipitation records; Precipitation data to DDF (rainfall frequency analysis); Precipitation data to Huff Curves; and DDF to Alternating Block Design Hyetographs. Data Tools group: GRIB to CSV conversion; NetCDF4 to CSV conversion (flatten or point extraction, for an arbitrary user-supplied NetCDF4 file) and its companion List NetCDF4 Variables discovery tool. Rainfall Tools group also includes Design Storm Ensembles, which builds Huff/ARR-style representative temporal storm pattern ensembles for 24 design durations and three AEP bands from a sub-daily rainfall record and a DDF table. Hydrological Tools group also includes D8 Flow Accumulation (WBT), an exact replication of WhiteboxTools' own D8FlowAccumulation tool that consumes either a raw DEM or this suite's own D8 Flow Direction plugin's pointer output directly. Rainfall Tools group also includes Extract: ERA5 precipitation, which reads ERA5/ERA5-Land total precipitation directly from the Copernicus Climate Data Store (CDS), for a point or point layer, over the full 1950-present record or a specified date range. v0.5.0 adds a second, selectable "Fast" access method using a separate, purpose-built CDS timeseries dataset - confirmed by live testing to retrieve the full 76-year record in around 40 seconds (versus multi-hour Standard-method runs) and to match the CDS website exactly; offered as an opt-in alternative, not the default, since ECMWF's own documentation labels that dataset experimental and not recommended for operational use. Hydrological Tools group also includes Catchment Delineation, which takes a D8 pointer and its DEM with pour points (snapped to flow accumulation) or pour lines and writes repaired catchment polygons (total or incremental), a catchment DEM, longest flow paths and a parameters report (area, shape, slopes, hypsometry, drainage density, and Kirpich, USBR/SANRAL and Bransby-Williams time of concentration). v0.2.0 adds geomorphometric parameters (Strahler stream order, bifurcation ratio, Melton ratio, relief ratio and more) and an optional Word (.docx) annexure report with parameter definitions, figures, a guideline-neutral catchment description and modelling considerations. v0.3.0 adds optional stream network (links split at junctions, with Strahler order, upstream area, slope and downstream link) and catchment centroid vector outputs. Rainfall Tools group also includes Adjust Sub-daily Rainfall to DDF, which adjusts a sub-daily gridded rainfall series (ERA5, IMERG, CMORPH...) so that its annual maxima at every tested duration match a reference gauge-based DDF while keeping the recorded storm timing (anchor-duration magnitude mapping plus mass-preserving nested peak-window scaling, with held-out validation durations, bootstrap intervals and an optional stochastic ensemble), and writes the adjusted series, a Word report and an optional storm library for Monte Carlo design storms. v0.2.0 adds a new HEC-RAS Tools group: Import RAS 2D data, ported from the standalone "Import RAS 2D Data" plugin, reads a finished HEC-RAS 6.x/7.0 2D-domain model's geometry - mesh (perimeter, cells, breaklines, refinement regions), SA/2D connections (bridges, weirs, culverts, linear routing), pump stations, boundary condition lines, initial condition points, reference lines/points/areas, and pipe networks - directly from its HDF5 file with h5py (no ras-commander dependency) into styled GeoPackage layers, one per selected element, in one tool run. Hydrological Tools group also includes DEM depression stage-storage, which reads stage-storage (elevation-area-volume) curves for ponds, dams, detention basins and natural depressions straight off a DEM inside storage-area polygons - fractional edge-cell coverage, connected-pool or level-pool counting, automatic spill level (with a per-feature or global maximum-stage override) - and writes a stage table CSV, a HEC-RAS / HEC-HMS elevation-volume table, water-surface polygons, a depth raster, spill points and an optional Word report with stage-storage, stage-area, depth-area and depth-volume curves. It fails with a clear message, rather than writing empty layers, when no polygon encloses a depression. Hydrological Tools group also includes Stream Network, which extracts the stream network from a D8 pointer and DEM (whole raster or upstream of pour points) and classifies every reach by Strahler, Shreve, Horton and Hack ordering in one line layer, with channel heads/confluences/outlets, main stems, a constant-drop test for the stream threshold, Horton ratios, reach routing inputs (velocity, travel time, Muskingum K and X), a sectioned CSV and an optional Word report. Catchment Delineation v0.4.0 writes the same stream network outputs as the Stream Network tool (reach layer with Strahler, Shreve, Horton and Hack orders and routing inputs, nodes, main stems, sectioned CSV and optional stream network Word report) for the network upstream of its outlets. Soil Tools group (new): Extract: SoilGrids 2.0, which reads ISRIC SoilGrids 2.0 soil properties (sand, silt, clay, organic carbon, bulk density, coarse fragments, pH, CEC; optional water content and SoilGrids 2017 depth to bedrock) at 250 m for six depths, for an area (multi-band GeoTIFFs) or points (CSV), with the 5/50/95% prediction quantiles and a metadata log of sources, units, quality checks and uncertainty. Soil Tools also has Extract: OpenLandMap Soils, which reads OpenLandMap-soildb (sand, silt, clay, organic carbon, bulk density, pH; optional SOC density) for 0-30, 30-60 and 60-100 cm and 2000-2022 at 30 m, with 120 m P16/P84 prediction intervals, for an area (multi-band GeoTIFFs) or points (CSV), with a metadata log of sources, scales, quality checks and uncertainty. v0.5.0 adds Regional soil parameterisation, which turns the SoilGrids and/or OpenLandMap extraction outputs into hydraulic soil parameters for 0-30, 30-60 and 60-100 cm - water contents at saturation, field capacity and wilting point, plant-available water, Ksat, Brooks-Corey parameters and the Green-Ampt wetting-front suction - with gap filling, a Monte Carlo uncertainty analysis (median and 90 % range, variance split by input data, product and method), quality rasters, a zone summary and a detailed Word report; Saxton & Rawls (2006) is the first ensemble method and Rawls, Brakensiek & Miller (1983) class values are a reference check. v0.5.1 replaces the pass/fail robustness with graded confidence (Ksat uncertainty factor and classes, texture-class confidence), shows each product's own medians beside the pooled result, and warns when the density adjustment is used. v0.6.0 adds Tóth et al. (2015) European pedotransfer functions - the method behind HiHydroSoil v2.0 - as a second method (Mualem-van Genuchten retention, Ksat from pH and CEC, Green-Ampt suction from the effective capillary drive), selectable alone or with Saxton & Rawls as an ensemble whose method spread enters the uncertainty. v0.6.1 adds candidate design parameters per zone and layer (areal geometric or arithmetic mean, P5-P95 sensitivity bounds, product x method range, effective K = 0.5 Ksat, a High/Medium/Low confidence rating and the main uncertainty source) in rsp_design_parameters.csv and a new report section with confidence, recommendations, limitations and risks, and redraws the report figures to a publication style. v0.6.2 adds a plain-language explanation of how confidence is judged to the report's purpose section. v0.7.0 adds Hydrologic soil groups, which assigns curve-number soil groups from the Regional soil parameterisation Ksat (P5/P50/P95), the depth to an impermeable layer (SoilGrids 2017 depth to bedrock, a raster or a constant) and the water-table depth, by USDA-NRCS NEH 630 Chapter 7 (2009, Table 7-1, with dual groups A/D, B/D, C/D) and/or the SCS-SA groups of Schulze, Schmidt & Smithers (2004, Table 2.1, with the intermediate groups A/B, B/C, C/D and the shallow-soil and water-table adjustments), with the probability of each group, a recommended group and its confidence, the groups at the Ksat P5 and P95, a zone summary of group shares, metadata and a Word report. v0.8.0 adds Extract: iSDAsoil (Africa), which reads iSDAsoil 30 m soil properties for Africa (sand, silt, clay, organic carbon, bulk density, pH, stone content, optional effective CEC, and depth to bedrock) for 0-20 and 20-50 cm with their mean and standard deviation, for an area or points, from the public iSDAsoil cloud-optimised GeoTIFFs; Regional soil parameterisation v0.7.0 accepts it as a third ensemble member (0-30 and 30-60 cm; not 60-100 cm) with pairwise product comparisons; Hydrologic soil groups v0.2.0 can use the iSDAsoil depth to bedrock with its standard deviation, so the confidence includes the chance that bedrock lies in another depth class. v0.9.0 adds a Land Cover Tools group with Extract: Land cover, which reads ESA WorldCover 10 m land cover (2021 v200 and 2020 v100, 11 classes) for an area or points from the public cloud-optimised GeoTIFF tiles, skipping open-sea tiles, reprojecting with nearest neighbour only, and writing Byte GeoTIFFs with the official colours embedded, a layer file, and a metadata CSV with citations, the tiles used and class areas; it is the land-use input for the planned curve-number tool. v0.10.0 adds Curve numbers (Land Cover Tools), which maps SCS curve numbers from a land-cover raster and the Hydrologic soil groups output through SCS-SA Table 5.1 (Schulze, Schmidt & Smithers 2004; groups A to D with A/B, B/C and C/D) or TR-55 / NEH 630, with built-in ESA WorldCover lookups (design, low and high rows per class; wetlands set to group D) or an editable custom lookup CSV; a P05-P95 range that combines the soil-group range (Ksat P5 and P95) and the land-cover condition range; optional antecedent-moisture adjustment (ARC I/III, Sobhani wet, SCS-SA Median Condition); zone summaries with the runoff-equivalent curve number for a design rainfall depth; metadata and a Word report with confidence, recommendations, limitations and risks. v0.11.0 adds DEM Hydrological Processing (Hydrological Tools), which corrects a DEM so every cell drains: it finds depressions with a depression hierarchy, fills or breaches each one (whichever changes the DEM less), and runs a drainage-enforcement pass that removes the pits those corrections can leave. The default is continuous drainage; genuine sinks (pans, regional sinks, lakes) are kept only when supplied as a polygon or point layer, and every supplied feature's match is reported. An optional persistence classification (Lindsay & Creed) can preserve Likely Natural depressions or be reused from an earlier table. Outputs are the corrected DEM, remaining sinks, a sectioned CSV and an optional Word report. v0.12.0 adds SANRAL Deterministic Peak Flows (Hydrological Tools): design peak flows per catchment by the SANRAL Drainage Manual (2013) Chapter 3 methods - Rational (Alternatives 2 and 3), Standard Design Flood, Midgley & Pitman, Kovacs RMF with QT/QRMF ratios - and the DWS (2025) Catchment Parameter method, with range-of-application flags, a sectioned CSV, a results.json for the report compiler and an optional Word annexure; verified against the Application Guide worked examples. v0.13.0: Curve numbers v0.2.0 adds a built-in South African National Land Cover (SANLC 2018 / 2020, 73 classes) lookup: urban, plantation and natural-vegetation classes take the preliminary calibrated SCS-SA curve numbers of WRC Report 2747/1/20 (Loots & Smithers 2020, Table 9.7, Tshwane) through a crosswalk to the DEA 2013/14 land-use types, other classes the nearest SCS-SA Table 5.1 row; open water 100, bare rock 98, herbaceous wetlands on group D; four Table 9.7 misprints corrected; low and high ends per class from neighbouring rows. v0.14.0: DEM depression stage-storage v0.3.0 can estimate the bed below a surveyed water surface (pans, ponds and dams whose DEM shows the water at the time of survey) as a low / central / high range - from the shoreline slope (Hollister et al. 2011), the hypsometry of the dry ground above the water (after Heathcote et al. 2015) and, for built dams with a stream centreline, the valley profile upstream and below the wall - and then runs the stage-storage curve from the estimated bed, with the low and high volumes in the table and report, DEMs with the estimated bed, the surveyed water surface and an optional HydroLAKES check. v0.15.0 adds DEM Inundation Boundary (Hydrological Tools): the extent of water standing at one elevation, within an optional bounding polygon, as a smoothed boundary line and matching polygons (dry islands as holes, cut at the bounding polygon), counting either all ground below the level or only ground connected to seed points; the outputs are ticked and written to raster, shapefile, CSV and Word folders as <project number>_<description> files - boundary, extent and water-surface elevation raster (ticked by default), depth raster, summary CSV and a Word report in the Mayim report standard - and the layers are loaded into the project styled. v0.16.0 adds Flood Extent Terrain Profile (Hydrological Tools): report-ready cross-sections and long-sections along section lines drawn on the map through a DEM, with one or more flood water-surface rasters and a development property, measuring the horizontal and vertical distances from the property boundary to the flood edge (or the wet length and depth inside the property) and the shortest plan distance to flooding, drawn 16.5 cm wide at a set vertical exaggeration in Arial and Arial Narrow (PNG, SVG, PDF), with profile and measurement CSVs and map layers of the sections, chainages, boundary crossings and flood edges. v0.16.1: Flood Extent Terrain Profile v0.2.0 - section lines are drawn on the map in the tool dialog (one or more, labelled A, B, C ...), every output (figures, CSVs, section line and point GeoPackages, plan-distance lines) is written to one output folder, and the section lines and points load into the map styled, with larger labels. v0.16.2: DEM Inundation Boundary v0.4.0 takes a single water level (the range option was removed) and writes the ticked outputs to one output folder, loading the layers into the map. v0.16.3: Flood Extent Terrain Profile v0.3.0 adds a plan view above the profile in a second, combined figure per section (the profile alone is still saved): the project's visible map layers fitted to the section, with the section line, chainage ticks, A and A', the property outline, flood edges, the shortest plan distance, a scale bar and a north arrow. v0.16.4: Flood Extent Terrain Profile v0.3.1 - the profile is titled 'Section A-A'' below its legend (source and exaggeration notes and end labels removed), the plan view renders every visible layer (rasters and remote basemaps included) without a scale note, and distance and chainage labels no longer overlap. v0.16.5: DEM Inundation Boundary v0.5.0 follows the Mayim report and figure standard - outputs ticked per kind and written to separate raster (GeoTIFF), shapefile, CSV (UTF-8 with BOM) and Word folders, named <project number>_<description>; the Word report uses the house text style, 16.5 cm chart-style figures and a QGIS-rendered layout map (depth, boundary, bounding polygon, seeds, DEM contours, OpenStreetMap background, legend, scale bar, north arrow). Word report tables in the house style now have the #ADADCC header shading. v0.17.0: Regional soil parameterisation v0.8.0 follows the Mayim output and report standards - one tick box per output, written to raster (GeoTIFF), CSV (UTF-8 with BOM) and Word folders as <project number>_<description> files; the USDA texture class is written as one raster per layer, styled with SOIL_USDA_classification.qml; new Green-Ampt (SWMM) outputs computed on every Monte Carlo draw - initial deficit for a dry start (theta_s - theta_1500) and a moist start (theta_s - theta_33), also as a depth in mm over the layer, and drying time T = 15.78/sqrt(Ksat) days; the candidate design table adds these with a Description column relating each value to the soil parameters and the SWMM inputs; the Word report is rebuilt in the house style (summary, tool and method, inputs and settings, parameters and calculations, results, outputs, notes and limitations, references) with chart-style figures and a QGIS-rendered USDA texture layout map per layer (OpenStreetMap background, zones as the study area, legend of the classes present, scale bar, north arrow). Hydrologic soil groups v0.3.0 finds the Regional Ksat and harmonised-inputs rasters in the raster folder by their band descriptions, so project-numbered names and older rsp_ folders both work. The report map frame and QGIS map rendering are now shared modules (_common/report_maps.py, _common/qgis_maps.py). v0.17.1: Regional soil parameterisation v0.8.1 - the report's USDA texture layout maps show the texture raster at 70 % transparency, take optional site boundary and catchment boundary polygon layers drawn above it in their project symbology, and fit the catchment with a margin (or the texture raster when no catchment is given). v0.18.0 adds Extract: DWS and WR2012 data (Hydrological Tools): for a study area it downloads the DWS water management areas (2023 by default, or 2012 / 2004), primary to quaternary drainage regions, quinary catchments, 1:50 000 rivers and dams and the Reserve status layers from the DWS ArcGIS services, selects DWS river, reservoir, rainfall, evaporation, groundwater and tidal station locations from a bundled table of the DWS verified station lists (September 2026), and - when a local WR2012 Coverages folder is given - adds per-quaternary MAP, naturalised MAR, Pitman parameters, rainfall and evaporation zones, A-pan MAE, EIS and PES classes, TDS, sediment yield and GRA II recharge, baseflow and exploitation values with an area-weighted water-balance summary; outputs follow the Mayim output and report standards (shapefile, CSV and Word folders, <project number>_<description> names, house-style report with a QGIS layout map). v0.18.1: Extract: DWS and WR2012 data v0.1.1 - after the first live run: the DWS ArcGIS Online copies are tried first for the drainage regions, rivers, dams and older WMAs (the gia root services did not answer with JSON); WMA and primary/secondary polygons are simplified on the server (about 50 m) and features are tested against a prepared study-area geometry for speed; the GRA II dry-recharge and baseflow grids are converted from m³/km²/a to mm/a; damaged WR2012 files (rain zones, GRA II exploitation factor) are reported clearly; the report map shows one set of quaternary labels and station codes only when there are 25 stations or fewer; elapsed times are logged. v0.18.2: Flood Extent Terrain Profile v0.3.2 follows the figure standard - all figure text Arial Narrow 9 pt (axis titles and the 'Section A-A'' title bold, legend italic), black 0.75 pt border on all four sides, major and minor gridlines (#BFBFBF / #F2F2F2), natural ground black 1 pt dashed, water surfaces 1.5 pt in the house colours with 12 % fills, property boundary red; the shared figure code finds fonts installed in the Windows or per-user font folders that matplotlib's font cache does not list (e.g. Arial Narrow). v0.18.3: DEM Hydrological Processing v1.1.0 follows the Mayim report and figure standard - outputs are ticked and written to per-kind folders (rasters, shapefiles, CSV, Word) as <project number>_<description>, with a new elevation change raster (corrected minus original) and project number / project name inputs; layers load with new QML styles (elevation change classes, remaining sinks); the Word report has a title page, the house structure (summary, method, inputs, parameters with equations, results, outputs, notes, references), a QGIS layout map of the elevation changes and remaining sinks over OpenStreetMap with optional study area and contours, and a house-style histogram; the classification CSV is UTF-8 with BOM. Saved Processing models need their DEM Hydrological Processing outputs set again. Shared: pseudocolour raster legends on report maps; short report tables are kept on one page and long ones repeat their header row. v0.18.4: report standard v2.1 contours - DEM Hydrological Processing v1.2.0 and Catchment Delineation v0.7.0 draw minor contours (fine, at the minor interval set by the user) and major contours (thicker, every 5 x the minor interval) on the report layout maps, with a tick box to leave contours off; when the minor contours would crowd the map only the major ones are drawn. Catchment Delineation v0.7.0: optional maximum stream length - each stream network reach is measured upstream from its lower end and split at a 'stream breakpoint' node at every maximum length, where the rest of the reach is longer than 10 % of the maximum (reach fields split_from and piece; the DRN_stream_nodes style gains a breakpoint category); project / site name input; the catchment report has the title page and the three-column parameter table of the report standard. The stream network Word report (Catchment Delineation and Stream Network) follows the report standard: title page, house text and chart styles, standard section order with a parameters table, and network maps in the house map frame with the QML colours. v0.18.5: Catchment Delineation v0.8.0 - Incremental mode now treats the pour point or line as the final outlet and divides its catchment along the stream network into named sub-catchments: one per stream (the reach between two nodes, after stream breakpoints) draining to the node at its lower end, and one per channel head, each with its own centroid and longest flow path; optionally each stream sub-catchment is split along the stream centreline into left (a) and right (b) banks. Names: main stem A (further outlets B, C ...), streams numbered upstream from the outlet (A1, A2 ...), branches named after the stream they join plus a letter (A3A1 ...); nodes take the name of the stream draining to them, and each sub-catchment records the node it drains to and the stream below (node, ds_stream) for model set-up. New inputs: minimum final reach length (% of the maximum stream length, default 10) and the centreline split; the incremental report lists every sub-catchment and its links, with a labelled overview map and parameter tables (a full section per sub-catchment is an advanced option). Streams and nodes are named in both stream tools (name, ds_name); node link ids now point to the top piece of a split reach; the DRN_stream_nodes style labels the node names. v0.18.6: Catchment Delineation v0.8.1 - the centreline split now delineates each stream sub-catchment whole and cuts it along its stream centreline (through the stream cell centres, extended to the boundary), so the bank polygons meet exactly on the centreline; a split tolerance (minimum piece area, default 10 cells, and minimum mean width = area / length along the stream, default 2 cells) merges slivers into the neighbouring piece they share the longest boundary with, same-side pieces stay one multi-part sub-catchment, and a stream whose whole bank fails is not split (counted in the run log).
